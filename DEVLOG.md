- **原型验证 / Prototype verification**：用 Playwright 跑通完整流程——三段式录入→保存→归因树长出新枝→点击叶子/症状/主干三种详情→规律统计更新，控制台零错误。过程中修掉四个真实缺陷：① 归因树布局的 `symY` 暂时性死区（整棵树不渲染）；② 身体部位用多选逻辑处理单选字符串（下一步按钮永久禁用）；③ 症状节点未 push 进渲染数组（只画出叶子）；④ 日期文字与触发标签重叠（标签点击被遮挡）。并按"低负担"目标做交互收敛：身体部位改 5 列紧凑网格、情绪默认折叠、触发可跳过、第 3 步实时回看。
  Prototype verification: drove the full flow with Playwright — three-stage capture → save → a new twig appears in the attribution tree → all three detail views (leaf / symptom / trunk) → pattern statistics update, with zero console errors. Four real defects were found and fixed along the way: (1) a temporal-dead-zone error in the tree layout (the whole tree failed to render); (2) single-select body area handled with multi-select logic (the "next" button stayed permanently disabled); (3) symptom nodes never pushed into the render array (only leaves appeared); (4) date text overlapping trigger labels (label clicks were blocked). The flow was also tightened for the low-burden goal: body area as a 5-column compact grid, emotions collapsed by default, triggers skippable, and a live review block on step 3.
